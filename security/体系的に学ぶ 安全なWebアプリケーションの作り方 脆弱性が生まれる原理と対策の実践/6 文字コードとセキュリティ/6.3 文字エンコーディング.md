# 文字エンコーディングとは

- 文字集合には符号がついているため、そのままコンピューター処理に使えば良いように思えるが、現実にはそう単純ではない
    - US-ASCIIやJIS X 0201などの1バイト文字集合が先に普及。これらの互換性を保ちつつ、JIS X 0208やUnicodeなど2バイト以上の文字集合を併用する必要性が生じた
    - 参考「代表的な文字集合(抜粋) 」
    
    <aside>
    ➡️
    
    このための符号化を「文字エンコーディング」あるいは「文字符号化方式」と呼ぶ
    
    </aside>
    

## Shift_JIS

- 日本でPCが普及し始めた1980年代初頭に、PCで漢字を扱うための文字エンコーディングの要求が出てきた
- この要求に対して、JIS X 0201の空き領域にJIS X 0208をマッピングする形でShift JISが作られた。
- 文字集合としてマイクロソフト標準キャラクタセットを用いるShift_JISは、マイクロソフトコードページ932, あるいはCP932と呼ばれる

### 文字コード：符号化文字集合と文字符号化方式、Shift_JISの仕組み(ChatGPT)

## 1. 「文字」と「コンピューター上のバイト列」は別物

人間が扱う「あ」「A」「漢」などの**文字**を、コンピューター上で扱うためには、文字に対して数値（符号）を割り当て、最終的にバイト列として表現する必要がある。

ここで重要なのが、

- **符号化文字集合（Coded Character Set）**
- **文字符号化方式（Character Encoding Scheme）**

を区別すること。

---

## 2. 符号化文字集合とは

符号化文字集合は、

> 「どの文字を扱うのか」そして「その文字にどの符号位置を割り当てるのか」
> 

を定義するもの。

例えばJIS X 0208では、日本語のひらがな・カタカナ・漢字などに対して符号位置が定義されている。

イメージ：

```
文字        符号位置
「あ」  →   JIS X 0208上のある位置
「漢」  →   JIS X 0208上のある位置
「A」   →   JIS X 0208上のある位置
```

つまり、**文字と符号の対応関係を定義するのが符号化文字集合**。

---

## 3. 文字符号化方式とは

一方、文字符号化方式は、

> 符号化文字集合で定義された符号を、コンピューター上で実際に扱うバイト列へどのように対応させるか
> 

を定義するもの。

したがって、

```
文字
 ↓
符号化文字集合
 ↓
符号位置
 ↓
文字符号化方式
 ↓
実際のバイト列
```

という流れで考えると分かりやすい。

「文字を全く別の文字コードに変換する」というより、

> **文字集合が定義している符号を、実際のコンピューター上のバイト列としてどう表現するか**
> 

を決めるもの、と考える。

---

# 4. Shift_JISを例に考える

Shift_JISは、日本語をコンピューターで扱うために作られた文字符号化方式。

歴史的には、PCで漢字を扱う必要が出てきたことから、既存のJIS X 0201の1バイト文字の領域を利用しつつ、JIS X 0208の日本語文字を2バイトで表現できるようにした。

ポイントは、

> **JIS X 0201とJIS X 0208を単純に横に並べるのではなく、Shift_JISというルールに従って、それぞれの符号をバイト列へマッピングしている**
> 

ということ。

---

# 5. JIS X 0201の1バイト文字

Shift_JISでは、JIS X 0201で扱われていた文字の一部を、1バイト文字として利用する。

例えばASCII系の文字なら、

```
JIS X 0201
「A」
 ↓
0x41

Shift_JIS
「A」
 ↓
0x41
```

のように、**JIS X 0201での1バイトの符号を、そのままShift_JISでも利用できる領域がある**。

したがって、

> 「JIS X 0201をさらに別のエンコーディングに変換してから、1バイト文字として割り当てている」
> 

というイメージではない。

むしろ、

> **Shift_JISの中でJIS X 0201の符号をそのまま利用している**
> 

と考える方が分かりやすい。

※厳密には「JIS X 0201そのものとShift_JISが完全に同一」という意味ではなく、Shift_JISという方式がJIS X 0201の符号領域を利用している、という関係。

---

# 6. JIS X 0208の文字は2バイトで表現する

一方、JIS X 0201の1バイトでは、日本語の大量の漢字などを表現できない。

そこでJIS X 0208の文字を2バイトで表現する。

ここで重要なのは、

> **JIS X 0208の符号をそのまま2バイトとして格納しているわけではない**
> 

という点。

概念的には、

```
JIS X 0208
「あ」
 ↓
JIS X 0208上の符号位置
 ↓
Shift_JISのルールによるマッピング
 ↓
Shift_JIS上の2バイト
```

となる。

つまり、JIS X 0208の符号位置とShift_JISの2バイト値は、**別の値になる**。

---

# 7. Shift_JISでは「先行バイト」と「後続バイト」を使う

Shift_JISの2バイト文字では、

```
1バイト目 → 先行バイト
2バイト目 → 後続バイト
```

として扱う。

画像の図にあるように、先行バイトには、

```
0x81 ～ 0x9F
0xE0 ～ 0xFC
```

などの領域が割り当てられている。

後続バイトには、

```
0x40 ～ 0x7E
0x80 ～ 0xFC
```

などの領域が使われる。

例えば概念的には、

```
[0x82] [0xA0]
   ↑      ↑
先行バイト 後続バイト
```

のように2バイトで1文字を表現する。

---

# 8. なぜ1バイト文字と2バイト文字を区別できるのか

Shift_JISでは、バイトの値域を工夫して、

```
1バイト文字
2バイト文字の先行バイト
2バイト文字の後続バイト
```

をある程度区別できるようにしている。

例えば、

```
0x81
```

を見たとき、

> 「これは普通の1バイト文字ではなく、2バイト文字の先行バイトかもしれない」
> 

と判断できる。

そして次のバイトと組み合わせて1文字として解釈する。

```
0x81 0x40
 ↑     ↑
先行   後続

        ↓

      1文字
```

このように、Shift_JISは**1バイト文字と2バイト文字を同じバイト列の中で扱えるように設計されている**。

---

# 9. 「変換している」という理解を整理する

今回の疑問だった、

> 「符号化文字集合から文字符号化方式にすると、全く別の符号が作られるのか？」
> 

については、**文字によって違う**と考えると分かりやすい。

### JIS X 0201系の1バイト文字

```
JIS X 0201の符号
      ↓
ほぼそのままShift_JISで利用
```

つまり、既存の符号を**そのまま利用する**。

### JIS X 0208系の文字

```
JIS X 0208の符号位置
      ↓
Shift_JISのルールでマッピング
      ↓
Shift_JISの2バイト値
```

こちらは、**JIS X 0208の符号位置をShift_JIS用の別のバイト値へ対応付ける**。

したがって、

> 「Shift_JISではJIS X 0201とJIS X 0208の文字を単純に組み合わせただけ」
> 

という理解は大枠では合っているが、より正確には、

> **JIS X 0201の符号領域を利用しつつ、JIS X 0208の符号位置をShift_JIS独自の2バイト表現へマッピングした**
> 

ということになる。

---

# 10. 「符号化文字集合」と「エンコーディング」を混同しない

今回一番重要なポイント。

```
【符号化文字集合】

どんな文字を扱う？
↓
その文字にどんな符号位置を割り当てる？
```

に対して、

```
【文字符号化方式】

その符号位置を
コンピューター上のバイト列として
どう表現する？
```

という役割分担がある。

したがって、

```
文字
 ↓
符号化文字集合
 ↓
符号位置
 ↓
文字符号化方式
 ↓
バイト列
```

という構造で覚えておくとよい。

---

# 11. 今回のShift_JISの理解

Shift_JISについては、最終的に以下のように整理できる。

```
JIS X 0201
 └─ 1バイト文字
      ↓
   Shift_JISの1バイト領域として利用

JIS X 0208
 └─ 日本語の漢字・ひらがな等
      ↓
   Shift_JISのルールでマッピング
      ↓
   2バイトで表現
```

つまり、

> **Shift_JISは、JIS X 0201の1バイト領域を利用しながら、JIS X 0208の文字を2バイトで表現できるようにした文字符号化方式**
> 

と捉えるとよい。

---

# 12. 16進数「0x」の意味

Shift_JISの説明で出てくる、

```
0x81
0x9F
0xE0
0xFC
```

などの `0x` は、

> **「この数値は16進数で表しています」**
> 

という意味。

例えば、

```
0x0A = 10進数の10
0x10 = 10進数の16
0x81 = 10進数の129
0xFF = 10進数の255
```

となる。

コンピューターでは1バイトが8ビットなので、表現できる値は、

```
00000000 ～ 11111111
```

つまり10進数では、

```
0 ～ 255
```

16進数では、

```
0x00 ～ 0xFF
```

となる。

そのため、**バイト値を表すときに16進数が非常によく使われる**。

---

# 13. 最終的なイメージ

文字コードについては、以下の4段階を意識すると整理しやすい。

```
① 文字
   ↓
   「あ」「A」「漢」など、人間が認識する文字

② 符号化文字集合
   ↓
   文字と符号位置の対応を定義

③ 文字符号化方式
   ↓
   符号位置を実際のバイト列へ対応付ける

④ コンピューター上のバイト列
   ↓
   0x41
   0x82 0xA0
   など
```

そしてShift_JISの場合、

```
JIS X 0201
  → 1バイト文字として利用

JIS X 0208
  → Shift_JISのマッピングを通して2バイト化

       ↓

Shift_JISのバイト列
```

となる。

- *「文字そのものを変換している」のではなく、「その文字をコンピューター上でどのバイト列として表現するかを決めている」**という視点を持つことが重要。

特に今回の理解では、

> **JIS X 0201の1バイト文字はShift_JISでその符号を利用する一方、JIS X 0208の文字はShift_JISの2バイト表現へマッピングされる**
> 

という対比を押さえておけばよい。
