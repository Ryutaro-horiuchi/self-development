# 5.4.1 ログ出力の目的

アプリケーションのログがセキュリティ上も重要である理由は以下の3点

- 攻撃や事故の予兆をログから把握し、早期に対策するため
- 攻撃や事故の事後調査のため
- アプリケーションの運用監査のため

# 5.4.2 ログの種類

- エラーログ
    - アプリケーションの様々なエラーを記録する
    - 攻撃の検出に役立つ場合がある
- アクセスログ
    - Webアプリケーションの情報閲覧や機能の利用記録としてのログ
    - Webアプリケーションが出始めた頃まで(2004)までは、アプリケーションのログはエラーログのみであったが、個人情報漏洩事件・事故への対応などを通して、正常系のアクセスログの重要性が認識され始めた
- デバッグログ
    - 文字通りデバッグ用のログ
    - デバッグログから個人情報や、クレジットカード情報が漏洩した事例もある

# 5.4.3 ログ出力の要件

## ログに記録すべきイベント

ログの使用目的から決定すべきだが、一般的には以下に示す認証・アカウント管理や重要な情報ひゃ操作に関するイベントを記録する

- ログイン・ログアウト
- アカウントロック
- ユーザー登録・削除
- パスワード変更
- 重要情報の参照
- 重要な操作(物品の購入、送金、メール送信など)

## ログの出力項目

4W1H(いつ、誰が、どこで、何を、どのように)に従った以下の項目を取得する

- アクセス日時
- リモートIPアドレス
- ユーザーID
- アクセス対象(URL、ページ番号、スクリプトIDなど)
- 操作内容(閲覧、変更、削除)
- 操作対象(リソースIDなど)
- 操作結果(成功あるいは失敗、処理件数など)

## ログの保護と出力先

- 保護
    - ログにパスワードやクレジット情報を含めてはならない
    - ログに対する不正アクセスができないよう保護
    - ログ自体に個人情報など機密情報を含めないよう制限、項目を省略できない場合はマスキングする
- DBやファイルがよく用いられるが、上記ログの保護の観点でログ専用のサーバーを用意することが望ましい

## ログの保管期間

- セキュリティ上の事件や事故の事後調査という目的を考慮すると、無期限で保存するという考え方もある
- 一方で、ログ自体に機密情報が含まれていた場合、保管期限を延ばすと情報漏洩の危険性が増加するというジレンマもある
- 定期的にログファイルを暗号化して別のメディアに記録し、普段は安全な場所に記録メディアを保管するなどの工夫が必要

## サーバーの時刻合わせ

- Webサーバー、アプリケーション、DB、メールなど各サーバーの時刻を同期させる必要がある。
    
    → NTPというプロトコルを用いてサーバーの時刻を合わせることがよく行われる
    

## アクセスログを要求するガイドライン

- 政府や各種団体の公開しているセキュリティガイドラインには、アクセスログの取得を義務付けているものがある
    - 個人情報の保護に関する法律
        
        ```
        8-6 技術的安全管理措置
        
        ...中略
        (3)外部からの不正アクセス等の防止
        ・ログ等の定期的な分析により、不正アクセス等を検知する
        ```
        
    - Pyament Card Industry(PCI)データセキュリティ標準(PCI DSS)
        - クレジットカー＠どの加盟店や決済代行事業者向けのセキュリティ基準
        
        ```
        要件１０: ネットワークリソーすおよびカード会員データのすべてのアクセスを追跡・および監視する
        ```
        
- 重要な情報の閲覧や重要な操作に関しては、監視や記録が必要
